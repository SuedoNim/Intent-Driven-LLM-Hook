Phase 0 Architectural Pivot Evaluation
Verdict: NO PIVOT. Proceed with Custom Minimal Code.

An evaluation of off-the-shelf orchestrators (n8n, Dify, LiteLLM, Open-WebUI) determined that existing 3rd-party platforms fail to fulfill the mandatory architectural constraints without introducing extreme bloat and insecure container-in-container workarounds:

  • 1. Ephemeral Rootless Podman Sibling Isolation: n8n/Dify cannot directly dispatch unprivileged sibling containers via rootless podman.sock with --network none and memory/CPU limits without running custom host scripts.
  • 2. Atomic SQLite WAL Intent Caching: No off-the-shelf router provides sub-millisecond local SQLite WAL resolution linked directly to executable script hashes with automated quarantine circuit breakers.
  • 3. FastMCP AST Pre-Flight Syntax Verification: Direct AST parsing (ast.parse) and entrypoint contract validation (def execute(data=None)) prior to containerization requires custom AST logic.
  • 4. Lightweight Quadlet Footprint: Custom Python (`uv` + FastAPI + FastMCP + HTMX) runs in a single <150MB RAM unit, whereas an off-the-shelf stack (Dify + Postgres + Redis + LiteLLM + Open-WebUI) consumes >3GB RAM.
